# Core migration evidence

DGP Core preserves the complete framework-neutral product-engine behavior of the legacy Digital Service Engine while accepting canonical DGP v1 definitions. This ledger assigns every legacy Core concern either to an implemented Core primitive or to the downstream package that owns the moved behavior.

| Legacy behavior | Legacy evidence | Destination | Preserved outcome | Implementation status | Tests/evidence | Explicit approval |
| --- | --- | --- | --- | --- | --- | --- |
| Builder lifecycle and state | `src/core/builder.ts`; Builder load/replacement tests | DGP Core canonical Builder | Hold and replace canonical definition state, refresh indexes and interpretation state, and expose a stable framework-neutral engine facade without local editor history. | Implemented by `ProductBuilder` | `index-graph-builder.test.ts` proves normalization, replacement, refreshed identity, options, visibility, save and graph composition | Not required—preserve through a new facade |
| Canonical authoring normalization | `src/core/normalise.ts`; normalization tests | DGP Core, consumed by Workspace authoring | Preserve canonical defaults, root/filter invariants, binding normalization, deduplication, recursive options, notices, fallbacks, effects, validation declarations, and deterministic collection shapes without legacy aliases. | Implemented by `normalizeProductDefinition` | `normalization.test.ts` covers empty/root branches, binding collapse, pricing inheritance, every declaration family, opaque metadata, non-mutation and canonical collections | Legacy compatibility removed; canonical behavior preserved |
| Constraint/capability inheritance | normalizer constraint propagation and tests | DGP Core resolver and Builder | Preserve effective values, ancestor precedence, malformed-tree termination, and origin evidence without persisting derived state. | Implemented as non-mutating capability resolution | Existing Core tests plus `visibility-effects.test.ts` cover ancestor conflicts, newly introduced descendant keys, origins and malformed cycles | Non-mutating representation approved; outcomes preserved |
| Product indexing and legacy NodeMap | `src/core/node-map.ts`, option traversal, NodeMap consumers | DGP Core `ProductIndex` | Preserve actual-ID filter/field/recursive-option lookup, option ownership, deterministic identity, and first-class node queries while adding lineage, descendants, relationships, and binding queries. | Implemented | Core index suites cover collisions, first-authored identity, recursive ancestry/descendants, roots, lineage, bindings and malformed cycles | Evolved abstraction approved; behavior preserved |
| Trigger resolution | `resolveTrigger()` and selection/editor consumers | DGP Core `ProductIndex` | Preserve direct trigger identity, kind, trigger key, and option-owner evidence without prefix guessing or derived path IDs. | Implemented by `ProductIndex.resolveTrigger` | Direct filter, button, recursive option and unknown cases plus owner/filter/ancestor evidence | Not required—preserve |
| Framework-neutral graph projection | `Builder.tree()` and Builder graph tests | DGP Core canonical Builder | Produce deterministic filter, field, recursive-option and service nodes plus hierarchy, binding, option, relationship, effect and service edges for Workspace `CanvasAPI`. | Implemented | Exact deterministic node order, unique edge identity, and all accepted edge families are covered in `index-graph-builder.test.ts` | Not required—preserve |
| Deterministic save preparation | `Builder.cleanedProps()` and cleanup tests | DGP Core canonical Builder, invoked by Workspace | Return canonical save output while pruning dead references, invalid option/effect targets, unbound excluded utilities, fallback aliases and derived or empty structures. | Implemented by `prepareProductDefinitionForSave` and Builder aliases | Cleanup tests cover recursive options, every relationship/effect map, orphan utilities, fallback scope/identity, schema version and canonical roots | Legacy wire aliases excluded; cleanup outcomes preserved |
| Builder options and contextual inputs | `BuilderOptions`, service map, selected triggers, policies, rate/fallback inputs | Core Builder plus owning package inputs | Preserve configurable selected-trigger and catalog interpretation inputs without making Core authoritative for publication validation, rates, charges, or host policy. | Implemented for Core-owned inputs; policies remain Validation-owned | Builder default/call override tests plus catalog/filter/fallback tests | Dependency split approved; behavior preserved |
| Builder validation integration | `Builder.errors()` and Builder validation tests | DGP Workspace composing DGP Validation | Preserve one-call editorial validation of current Builder state, including catalog/rate/policy inputs, without introducing a Core-to-Validation dependency. | Correctly excluded from Core; downstream Workspace composition pending | Core boundary check rejects Validation; Workspace–Validation integration is tracked in the Workspace ledger | Package dependency direction approved |
| Filter lineage and relationships | `src/core/visibility.ts`, tag-relation tests | DGP Core | Preserve root/self traversal, explicit rather than child inheritance, lineage, descendants, and deterministic termination on malformed cycles. | Implemented | Relationship cases are distributed across index and visibility suites with exact root/self/ancestor/descendant/unrelated outcomes | Not required—preserve |
| Field visibility and ordering | visibility implementation and tests | DGP Core | Preserve lineage-bound fields, direct active-filter rules, closest-trigger precedence, equal-depth exclusion, natural authored order, and `order_for_tags` pinning. | Implemented | Existing and replacement suites cover static/dynamic, ancestry, unrelated triggers, exclusion and ordering outcomes | Not required—preserve |
| Recursive options and effects | options, visibility, selection, editor, and ordering tests | DGP Core interpretation; Workspace/Ordering apply their owned state changes | Preserve recursive discovery, ownership, traversal order, forced visibility, option narrowing, active-filter/selected-trigger relevance, and declaration ordering. | Core interpretation implemented; customer-state application remains Ordering-owned | Recursive indexing/filtering, forced visibility, narrowing, trigger relevance and active-filter-first value effects have replacement cases | Not required—preserve |
| Service bindings, capabilities, and filtering | service filter, fallback, governance, and related tests | DGP Core | Preserve filter, button-field, recursive-option binding, capability matching, canonical string-key lookup, exact configurable rate-policy evidence, deterministic order, and multi-context fallback eligibility without claiming pricing authority. | Implemented | `services-fallbacks.test.ts` covers every rate policy, nullable rates, numeric/string identity, rejection reasons, node/global order and fails-not-all multi-context behavior | Not required—preserve |

Legacy publication validation and dynamic policy tests are assigned to DGP Validation; `Builder.errors()` integration is assigned to Workspace; fallback-editor mutations are Workspace-owned; customer state and effect application are Ordering-owned. All remaining applicable legacy Core behavior is implemented and covered here. No behavior is retired by this ledger.
